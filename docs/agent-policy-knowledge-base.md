# Agent 规则知识库整理

当前我们先把“适合频繁修改、适合给人读、适合前端展示”的规则抽成知识库，而不是一口气把所有执行逻辑都改成配置。

## 已整理到知识库的内容

- `商品编号`、`自动退款上限`、`情绪转人工阈值` 这 3 个可编辑字段定义
- 情绪等级字典：`satisfied / calm / anxious / dissatisfied / angry`
- 售后方案说明：`仅退款 / 退货退款 / 补发 / 部分退款`
- 常见问题场景与默认证据说明

知识库文件位置：

- [policy-knowledge-base.json](/D:/ecommerce-after-sales-system-codex-test-ai-module-merge/src/main/resources/agent-knowledge-base/policy-knowledge-base.json)

## 为什么先这样拆

这些内容有 3 个共同特点：

- 改动频率高
- 更偏“业务知识”而不是“程序判断”
- 需要同时给前端展示、给后端校验、给 Agent 理解

所以先抽出来最划算，后面无论是做商家规则编辑页、运营后台还是知识维护，都能复用这份定义。

## 还留在执行链里的内容

下面这些暂时不直接知识库化，仍由执行逻辑负责：

- 状态流转
- 风险判断
- 转人工判定
- 工单规划
- 回复编排

原因是它们目前不仅是“知识”，还是“带上下文的决策逻辑”。如果现在硬拆成纯配置，系统会先变碎，稳定性反而会下降。

## 下一步建议

如果后面继续整理，我建议按这个顺序做：

1. 把前端规则编辑表单直接改成读取知识库字段定义渲染
2. 把情绪阈值校验、中文标签、排序全部统一走知识库
3. 再把 `scene -> 默认证据` 从多处默认值统一收口到知识库
4. 最后才考虑把部分售后方案命中规则进一步配置化
