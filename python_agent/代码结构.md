# Python 售后 Agent 代码结构

## 职责边界

- Java 管理订单、工单、会话、权限、事务和最终状态；MySQL 是业务事实来源。
- Python 负责会话工具规划、知识检索、图片核验和正式审核建议，只通过 Java 内部接口更改业务状态。
- PostgreSQL/pgvector 保存知识，Redis 保存短期幂等与缓存，Kafka 投递正式审核事件。

## 主要目录

```text
after_sales_agent/
├─ agent/
│  ├─ agent.py                    # HTTP/Kafka 共用入口
│  ├─ router.py                   # 按已知事件类型路由
│  ├─ facts/                      # 带来源和可信等级的案件事实
│  ├─ safety_guards.py            # 会话安全规则
│  └─ workflows/
│     ├─ consultation/            # 有界 ReAct：plan → act → observe → plan/finalize
│     └─ formal_review/           # 单张正式审核图与确定性 Gate
├─ tools/                         # 角色白名单、工具参数和结果契约
├─ application/                   # 情绪、RAG 查询改写、知识入库等用例
├─ retrieval/                     # pgvector/pg_trgm、RRF、reranker
├─ providers/                     # LLM、视觉模型与 reranker 客户端
├─ integrations/                  # Java 内部 Agent API 客户端
├─ infrastructure/                # Trace、指标、checkpoint、可靠性机制
├─ interface/                     # HTTP 聊天与 Kafka 审核入口
├─ domain/                        # 领域模型
└─ config/                        # 运行配置
```

## 会话主链路

```text
Java /api/chat → interface/http_server.py → interface/http_adapter.py
→ AfterSalesAgent.handle_chat → ConsultationWorkflow
→ 已选订单先由 Java 核验归属并建立事实账本
→ plan（原生 Function Calling，只读白名单）
→ act（可信参数注入、并行查询、事实与来源记录）
→ plan 或 finalize（轮次与工具预算、可信政策校验）
→ Java 持久化答复、记录提交前补证请求或转人工
```

模型只选择只读工具。`append_chat_message`、`request_missing_evidence` 和 `handoff_to_human` 由工作流执行，模型无法直接调用。独立只读查询可并行；规划轮次、工具次数和重复调用都有上界。用户身份来自 Java 网关，商家和品类过滤条件来自 Java 核验的订单，附件来自本次请求，不由模型指定。事实账本保留来源、时间和可信等级；冲突转人工。提交前描述不清时只问一个澄清问题，凭证不足时只询问可信政策明确要求的一项凭证。

## 正式审核主链路

```text
Kafka → AfterSalesAgent.start_formal_review → FormalReviewWorkflow
→ 从 Java 加载可信上下文 → 输入预检
→ 输入缺失：记录补证并等待同一审核请求恢复
→ 输入完整：并行政策检索与图片核验
→ 单份 ReviewAssessment → 常规提案或受限复杂综合
→ 确定性 Gate → Java 提交审核建议或转人工
```

进入并行评估后不再回到补证节点。模型超时、JSON 无效、政策不可信和凭证不可核验均失败关闭；Kafka 超时取消与 Java 的审核请求及证据版本校验阻止迟到结果覆盖业务状态。

## 运行验证

在仓库根目录使用 `python_agent/.venv/Scripts/python.exe -m pytest python_agent/tests -q`。完整服务通过 `docker compose up -d --build` 启动，运行配置与凭据分别见根目录和 `python_agent/` 的本地 `.env`。
